# 花笺 Workbench

一个放在电脑上的温柔工作角落。把日历、待办、专注、便笺和桌面贴图放在一起，适合个人安排和日常行政办公。

**Windows 10 / 11，64 位。数据保存在本机。**

1.2.0 提供新的浅色界面，以及 Windows 安装版自动检查、下载和校验更新。

## 下载与运行

到 [Releases](https://github.com/AureliusWu/Workbench/releases) 下载 `Workbench-Setup-1.2.0-win-x64.exe`，双击后自动安装并打开工作台，无需安装 Node.js 或浏览器。安装在当前 Windows 用户下，默认程序位置为 `%LOCALAPPDATA%\Programs\Workbench`，创建“花笺 Workbench”桌面及开始菜单快捷方式。

以后下载新版 `Workbench-Setup-版本号-win-x64.exe` 再次打开，安装程序会识别同一份已安装程序并更新。任务、便笺、复盘、设置与本机加密密钥保存在独立数据目录，安装和正常卸载均保留这些记录。更新前可以先在设置中导出一份备份。

如果此前使用 1.0.1 便携 EXE，首次安装会继续读取同一份 `%APPDATA%\Workbench` 数据。旧便携 EXE 可能放在任意文件夹，安装程序不会删除或改写该文件；以后请使用新的“花笺 Workbench”快捷方式打开。升级前从托盘退出旧程序，避免继续运行旧便携文件。

发行版尚未购买代码签名证书，Windows 可能显示发布者未验证。请只从本仓库发行页下载，并用发行页中的 SHA-256 校验值确认文件来源。

## 自动更新

1.1.0 及更早版本需先手动安装 1.2.0。安装版默认在后台检查并下载新版，校验成功后，右上角会提示「有新版」。选择「重启更新」时先保存本机记录，再覆盖安装并重新打开。右上角「应用更新」可手动检查或关闭自动下载。便携版可在发行页下载新版。

更新器通过 Workbench 自带的 Ed25519 公钥验证发行清单，并核对安装包 SHA-256。安装器仍为未做 Windows Authenticode 签名的版本。发布步骤见 [安装与更新约定](docs/INSTALLER.md)。

## 能做什么

- **今天与日历**：日历与有日期的待办共用同一份数据，显示农历、节日与节气倒计时。
- **待办与小步骤**：设置优先级、日期、时间、提醒和重复规则；大事拆成可逐项打勾的小步骤，完成后划线。
- **全局搜索**：按 `Ctrl + K` 搜索待办、子步骤和便笺正文。周日历可直接勾选完成。
- **安排大任务**：给出预计总时长与每天可投入时间，按工作日拆分安排。
- **番茄钟**：开始、暂停、重置专注与休息，完成专注后累计记录。
- **随手记**：记录临时想法，也可把便笺单独置顶在屏幕上。
- **周复盘**：查看真实完成率与专注记录，保存个人复盘；可选连接自己的 AI 服务获取建议。
- **截图与贴图**：框选截图后直接置顶，也可把剪贴板中的图片钉在屏幕上作为参考。
- **文件聚合**：选择一个本地文件夹，按类别浏览并打开文件。
- **本地备份**：导出、导入 JSON 数据备份，便于主动保存和换电脑迁移。

本版以 Windows 本地使用为范围。参考资料中的手机账号同步、新闻订阅、OCR、长截图、录屏属于其他产品能力，不包含在本版承诺中。

## 月末周六规则

默认启用“每个月最后一个周六上班”。判断优先考虑中国大陆官方放假安排：**遇官方假期仍休息**，不会因为月末周六被改为上班；其余日期结合官方调休与普通双休日判断。

日历提供手动调整日期状态的入口。官方假期数据有明确适用年份，超出已收录年份会显示提示，不能视为已经获得当年的官方调休安排。详细来源和规则见应用中的日历说明及 [日历数据来源](docs/CALENDAR-SOURCES.md)。

## 提醒、问安与后台运行

提醒和每日问安需要 Workbench 进程运行。关闭主窗口后保留托盘，使用托盘菜单可重新打开或彻底退出；彻底退出、电脑关机时不会弹出提醒。Windows 的通知设置、专注助手也可能影响通知显示。

可以在设置中开启登录后启动。请按自己的使用习惯选择，默认不强制开启。

## AI 复盘

无需 AI 也可查看统计、使用本地建议并保存复盘。需要外部 AI 建议时，在设置中填写兼容接口地址、模型和自己的 API Key。

只有主动点击生成 AI 复盘时，才会将该次复盘所需内容发送给所配置的服务；服务可能收费，请使用自己的账户。API Key 由 Windows 本机加密保存，不写入导出备份，也不跟随 GitHub 源码上传。AI 建议仅供参考，请自行核对。

## 数据与迁移

数据保存在 Windows 当前用户的 `%APPDATA%\Workbench\workbench.json`，运行文件所在位置与数据位置分离。覆盖安装新版本不会清除此目录；Windows 正常卸载也保留记录，重新安装后可继续使用。

建议定期在设置中“导出备份”，将 JSON 保存到你选择的位置；换电脑后运行 Workbench 并“导入备份”。导入会替换工作台当前数据，请先导出已有内容。API Key 需要在新电脑重新填写。

源码、发行文件与个人记录分别保存；仓库不会包含你的任务、便笺、截图或密钥。

## 开发

需要 Node.js 22.12+，推荐 Node.js 24 LTS，以及 Windows 10/11 x64。

```powershell
npm ci
npm run build
npm start
```

前端热更新：

```powershell
npm run dev
# 另开一个 PowerShell
$env:WORKBENCH_DEV_URL = 'http://127.0.0.1:5173'
npm start
```

测试与打包：

```powershell
npm test
npm run test:native
npm run build
npm run test:e2e
npm run dist
```

`release/` 包含 `Workbench-Setup-版本号-win-x64.exe` 一键安装程序。需要额外制作便携包时可运行 `npm run dist:portable`，产出 `Workbench-Portable-版本号-win-x64.exe`。

端到端测试使用独立临时数据目录，不修改日常记录。`npm run test:installer` 仅允许在 GitHub 托管的临时 Windows 测试账户中执行，验证真实安装、覆盖升级、旧数据及密钥保留和卸载；在日常本机运行会拒绝修改安装注册表。可通过 `WORKBENCH_INSTALLER` 或 `-InstallerPath` 指定待测安装包，详见 [安装与升级约定](docs/INSTALLER.md)。

运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/generate-icon.ps1` 可重新生成图标。
